# Spec: Namespaced core skills with deprecated aliases

Ticket: local:specs/tickets/149-1-namespaced-skills.md (child 1 of 3 of gh:149) · Size: standard · Status: approved

## Problem
Core skills `work`, `review`, `plan`, `aws` and `terraform` have bare names that can shadow a harness built-in or a user's own skill when `brainrc apply` links them. This child ships the namespaced `brainrc-` names and keeps the old names as deprecated aliases for one minor release. It covers AC1, AC2, AC3, AC8 of `specs/149-namespace-core-skills/spec.md`. The parent's decisions stand: prefix `brainrc-`, five names, additive only, aliases removed at the next minor.

## Goals
- Five new skills exist under `skills/brainrc-<name>/` with the old behavior and content.
- Each old name still works, says it is deprecated, and never adds a second auto-trigger.
- Users who type `/work`, `/review`, `/plan` keep working; the new commands are `/brainrc-work`, `/brainrc-review`, `/brainrc-plan`.

## Non-goals
- Reserved-name check in `validate` (child 149.2); docs, Domains table, evals, changelog fragment (child 149.3).
- Removing any old name; renaming other skills, agents or commands; changing what the skills do.

## Acceptance criteria
- **AC1**: Given the repo, when skills are listed, then `skills/brainrc-{work,review,plan,aws,terraform}/SKILL.md` exist, each with frontmatter `name` equal to its directory, and the body, `argument-hint` and `disable-model-invocation` of the old skill unchanged (content moved with `git mv`; any bundled files move with it).
- **AC2**: Given a fresh `brainrc apply` (or plugin install), when skills are linked, then both `brainrc-<name>` and the old `<name>` are present for all five.
- **AC3**: Given each old-name `SKILL.md`, when read, then it is short, says it is deprecated, names `brainrc-<name>` as the replacement and the release that removes it (the next minor after the one shipping this), and tells the model to carry out the replacement skill with the same arguments.
- **AC4**: Given the old `work`, `review` and `plan` aliases, when invoked as `/work`, `/review`, `/plan` with their usual arguments, then the same task is performed and `argument-hint` is kept so completion is unchanged.
- **AC5**: Given any old-name alias, when its frontmatter is read, then `disable-model-invocation: true` is set (including `aws` and `terraform`, which are auto-triggered today), and its `description` is a deprecation notice, not the old trigger text. The new `brainrc-aws` and `brainrc-terraform` keep the original trigger descriptions, so each pair has exactly one auto-triggerable member.
- **AC6**: Given existing references that use the old names (spec-agent Domains table and `../aws/SKILL.md` / `../terraform/SKILL.md` links, `/work` mentions, pack `domains` entries), when `validate` runs, then it passes and each link resolves to a file (the alias).
- **AC7**: Given a plugin build, when generated, then it lists both the new and the alias skills, and `validate` fails if the committed manifest is stale.
- **AC8**: Given the unit tests, when run, then they cover AC1, AC3, AC5 and AC7, including a near-miss (an alias that is missing `disable-model-invocation`, or a stale manifest) that fails.
- **AC9**: Given `python3 scripts/brainrc.py validate` and the test suite, when run, then both pass.

## Constraints
- Stdlib only; no new dependencies. `dist/`, `.claude-plugin/`, `.cursor-plugin/` and the root `plugin.json` are regenerated by tooling, not hand-edited.
- Packs that name `work`, `review`, `plan`, `aws` or `terraform` must keep resolving through the window.
- Alias text carries no per-user or employer content.

## Requirement changes
None.
