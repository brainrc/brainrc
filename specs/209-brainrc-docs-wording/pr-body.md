Finish the rename: docs, messages and identifiers say brainrc

## Why
After the code moved to `brainrc` (#230, #232, #233, #234), the words had to follow, because users
meet the name first in the README, help text and error messages. 6 of 6 in epic #199 (rename to
brainrc), after #234.

## What changed
- Docs, README, AGENTS.md, CONTRIBUTING.md, spec-agent's skill files, the example pack and config
  comments use `brainrc` commands, the `~/brainrc` checkout, `~/.config/brainrc` / `$BRAINRC_HOME`,
  the `brainrc/` package and `brainrc@brainrc`. The tutorial runs clean with the new commands.
- Usage, doctor findings, errors, the `GENERATED by` banner and guard denial reasons say `brainrc`.
- Internal names: `aicfg_home()` is now `settings_home()`, with `aicfg_home` kept as a deprecated
  alias until 0.5.0. `home_origin()` says `legacy_env`, temp files use `.brainrc-` prefixes,
  `tests/test_aicfg.py` became `tests/test_brainrc.py`, and the repo's pre-commit hook id is
  `brainrc-validate`.
- New `tests/test_old_names.py`: any `aicfg` / `ai-config` outside `CHANGELOG.md`, `changelog.d/`,
  `specs/` and a narrow, reasoned allowlist (compatibility code, the tests that exercise it, kept
  on-disk names, upgrade notes) fails the suite. A stale allowlist row also fails.
- Living specs say `brainrc` for commands a user runs.
- **[pack contract]** changelog fragment. The `aicfg` command, `scripts/aicfg.py`,
  `python -m aicfg`, `import aicfg`, `AICFG_HOME` and `~/.config/ai-config` warn until 0.5.0 removes
  them. Old hook dirs and backups converge on the next apply, and doctor flags the old plugin.
