# Plan: Plugin and marketplace are named brainrc; doctor flags the old plugin

Spec: [spec.md](spec.md) · Status: approved

## Callouts
- **New dependencies:** none
- **Public API / contract changes:** plugin and marketplace rename `ai-config@ai-config` -> `brainrc@brainrc`; skills/roles become `brainrc:<name>` (`/brainrc:work`). Every Claude Code, Codex and Cursor plugin user must uninstall and reinstall. Packs that declare plugin `"dependencies": [{"name": "ai-config"}]` must change to `brainrc` (pack contract). New doctor WARNs (exit code unchanged).
- **Migrations / data changes:** none (doctor only reads `~/.claude/plugins/installed_plugins.json` and `~/.cursor/plugins/local/`; users move by hand per install.md)
- **Security triggers touched:** doctor reads another tool's file in the user's home; parsed tolerantly, never written (T2 `review: each`)
- **Domains:** scripting
- **Environments affected on deploy:** none; on merge the release workflow tags the version and users pull it
- **Destructive or replacing changes:** none
- **Version bump:** `bump: minor` with **[pack contract]** (CHANGELOG policy: breaking pack contract in 0.x). This releases **0.5.0**, the version the `aicfg` shim and legacy-home warnings say removes them (`SHIM_REMOVED_IN` in `brainrc/cli.py`), and packs pinned `requires_core = ">=0.4, <0.5"` (docs/packs.md example) will fail compat. Owner to confirm minor vs. `patch` + [pack contract] (as 0.4.2/0.4.3 did).

## Approach
`brainrc/plugin.py` holds the only name sources, `PLUGIN_NAME` and `PLUGIN_AUTHOR`; change them to `brainrc` / `brainrc contributors`, then run `python3 scripts/brainrc.py plugin` (`cmd_plugin`) to rewrite the committed manifests. `check_plugin` already compares committed files with `plugin_manifests()`, so validate flags an old-name manifest as stale with the `plugin` fix (AC2) with no new code; `release.py` keeps calling `cmd_plugin`.

Doctor gets one helper, `_old_plugin_findings()`, beside `_home_findings()` and appended in `doctor_findings()` the same way. Cursor: `(Path.home()/".cursor/plugins/local/ai-config")` exists or `is_symlink()` (a broken link counts) -> one WARN. Claude Code: read `~/.claude/plugins/installed_plugins.json`, catching `OSError`, `UnicodeDecodeError`, `json.JSONDecodeError`; require a dict root and a dict `plugins`; exact key `ai-config@ai-config` -> one WARN naming `tilde(path)`, fix `/plugin uninstall ai-config@ai-config`, then `/plugin marketplace remove ai-config`. Findings are `("WARN", what, fix)`, so `cmd_doctor`'s exit code is untouched. The new name's presence is not checked: old alone and old-with-new give the same WARN (AC8, AC10).

Docs change only lines where the plugin name is now wrong; `~/ai-config` clone paths and `aicfg` wording stay for #209. Cursor link becomes `ln -s ~/src/ai-config ~/.cursor/plugins/local/brainrc`.

## Risks
- `installed_plugins.json` layout is unverified; mitigated by the tolerant parse and the AC11 tests (any odd shape = silence).
- A user's own Cursor plugin named `ai-config` gets a false WARN; the fix says to remove it only if it is the old brainrc plugin.
- Real HOME leaking into tests; mitigated by patching `HOME` per test as `tests/test_doctor_home.py` does.

## Test strategy
Unit tests only, offline. T1: `PluginTest` in `tests/test_aicfg.py` (names, author, root `plugin.json`, no `ai-config` in any manifest, old-name manifest -> `check_plugin` stale + `brainrc.py plugin`, install id `f"{market}@{entry}" == "brainrc@brainrc"`). T2: `_old_plugin_findings()` against a temp HOME, each AC11 shape, a broken-symlink case, and a before/after snapshot (paths, mtimes, bytes) proving nothing is written; `cmd_doctor()` returns 0 with only the WARN. T3: doc string checks; old ids allowed only in install.md's move-from section.
